# 本地 Markdown 发布指南

本站文章由 `client/src/content/blog/<年份>/` 中的本地 Markdown 文件自动导入。目录按发布日期年份分层，结构与站点参考项目保持一致。新增或修改文件后，开发环境会重新读取内容；保存一个新的项目版本后，即可将更新的静态文章交付给访问者。

> 每一篇文章都是一个独立的 `.md` 文件。文件名用于辅助定位；文章的公开链接由 Frontmatter 中的 `slug` 决定。

## 文章文件结构

```text
client/src/content/blog/
├── 2025/
│   └── an-older-note.md
└── 2026/
    ├── my-new-note.md
    └── another-note.md
```

每份文件以 Frontmatter 开始，随后是标准 Markdown 正文。站点会从正文计算预计阅读时间，并自动把文章列入首页、文章索引与搜索结果。

| 字段 | 是否必填 | 用途 | 示例 |
| --- | --- | --- | --- |
| `title` | 是 | 文章标题 | `写给未来自己的接口` |
| `slug` | 是 | 文章访问路径，需保持唯一 | `interfaces-for-future-me` |
| `date` | 是 | 排序与显示日期，使用 `YYYY.MM.DD` | `2026.08.20` |
| `category` | 是 | 文章分类标签 | `构建` |
| `summary` | 是 | 首页、列表与文章页导语 | `一句概括文章观点。` |
| `visual` | 否 | 文章插图的可访问地址 | `/manus-storage/example.png` |

## 最小可发布模板

```markdown
---
title: 写给未来自己的接口
slug: interfaces-for-future-me
date: 2026.08.20
category: 构建
summary: 好的接口会把当下的判断留给未来的使用者。
---

从这里开始写正文。

## 一个小标题

支持段落、**加粗**、*强调*、链接、引用、无序列表、有序列表和代码块。
```

## 发布前检查

新建文章时，请先按 `date` 的年份选择或创建对应目录，再确认 `slug` 没有和其他文章重复、日期格式正确，并且摘要可以脱离正文独立阅读。若要使用图片，请先将图片作为站点资产上传，并在 `visual` 中填写返回的访问地址。不要把大图片直接放入文章目录。

站点已支持常用 Markdown：标题、段落、强调、引用、列表、链接、图片和代码块。阅读时间会根据每篇文章的正文文字自动估算；无需手动填写。
